## 변경한 동작

- 포트폴리오 상단에서 같은 24kV 후보의 R1·R2·R3 판정을 함께 비교한다.
  근거를 펼치면 해당 주장에 실제로 등록된 국가·제품군·프로젝트 단계·추가 조건을 표시한다.
  `VERIFIED`, `ALLOWED`, `FIT`의 의미를 구분한다.
- 기록 구분과 세 입력란의 필수 여부, 완료 수, 남은 항목을 안내한다.
  공백만 있는 입력은 완료로 세지 않는다. 기록의 내용과 AI/사람 구분은 자동 생성하지 않는다.
- 인쇄할 때 모든 개정본과 접힌 근거를 펼치고, 인쇄 후 기존 펼침 상태·개정 선택·입력을 복원한다.
  스타일과 브라우저 코드는 읽기 쉬운 별도 모듈로 관리하며 생성 HTML은 여전히 단독 파일이다.
- 리뷰 상세 화면은 상태 변경이나 버전 충돌 뒤에도 같은 리드의 미저장 피드백을 유지한다.
  수동 메모는 목록·상세에서 서버/네트워크 오류가 나도 입력을 유지하고 실패와 재시도 방법을 표시한다.
  버전 충돌은 최신 상태를 확인한 뒤 사용자가 다시 저장해야 하며 자동으로 덮어쓰지 않는다.
- 저장/지우기 응답을 기다리는 동안 새로 입력한 값과 되돌린 값을 보존한다.
  미저장 입력이 있으면 페이지 이탈을 경고하며, 접근이 거부되거나 다른 리드의 응답을 받으면 보호된 초안을 제거한다.

## 검증 범위

회귀 테스트는 실제 실패를 먼저 확인하고 수정 후 통과를 확인했다.
포트폴리오의 사례 지문은
`121e688d98bf86eec032ac7e59d3677f33d92cb5c2ed8fc49598d6d6fa8f7754`로 유지한다.
고정 fixture와 엔진 결과, JSON 기록 schema, 오프라인 실행, CSP, AI 시뮬레이션 표시는 변경하지 않았다.

Node **24.22.1**에서 최종 검증을 완료했다. 아래 합계는 서로 다른 세 실행의
테스트 수만 더하며, 별도 집중 테스트나 CI gate 안에서 반복한 테스트는 중복 합산하지 않는다.

| 최종 검증 | 결과 |
| --- | --- |
| `npm test` | 루트 252 + Worker 단위 443 + 계약 30 = **725 통과** |
| `npm run test:e2e:local` | **51 통과** |
| `npm run test:worker:runtime` | **11 통과** |
| 합계 | **787 통과**, 실패·skip·TODO 0 |
| `check:naming`, `check:schema`, `git diff --check` | 통과 |
| `check:level1` 및 기존 CI 추가 gate 8종 | 모두 exit 0 |
| 독립 코드 리뷰 | **PASS** — 확인된 두 경합 수정 후 회귀 4개 재확인 |

기존 CI 추가 gate는 `security:audit-triage`, `check:enrichment-boundary`,
`check:enrichment-replay`, `audit:claims`, `eval:spec-fit`, `test:claim-spec-fit`,
`check:lead-pipeline-replay`, `eval:lead-quality`다. 이 코드 변경과 무관한 gate도
새 작업 환경에서 확인했고, 편집한 리뷰 화면에 관련된 Level 1은 수정 후 다시 실행했다.

독립 리뷰는 목록 갱신 중 저장 응답이 이전 객체에만 반영되는 문제와,
접근 거부 전 시작된 목록 조회가 보호된 필드를 복원하는 문제를 재현했다.
현재 리드를 다시 찾아 버전을 비교하고, 접근 거부 전 요청의 응답을 폐기하도록 수정했다.
첫 통합 브라우저 실행의 실패도 보존했다. 기존 저장 표시를 복원하고,
초안이 있는 입력 영역을 펼쳐 유지하는 새 동작에 맞춰 테스트의 대기 조건을 고쳤다.
입력 보존·요청 내용·명시적 저장 검증은 유지했으며 최종 전체 실행에서 모두 통과했다.

변경 소스 지문과 실행 범위는 [검증 JSON](review-experience-2026-10-29-verification.json)에 기록한다.
이 지문은 해당 검증 시점의 스냅샷이다. 이후 파일럿용 npm 명령을 추가한 `package.json`의
지문은 달라졌으며, 최신 파일럿 검증 JSON에서 변경 이유를 확인할 수 있다.
로컬 실행 로그는 `tmp/codex/portfolio-v1/verification/`, 구현/독립 리뷰 기록은
`tmp/codex/`, 화면 캡처는 `output/playwright/`에 보관한다. 이 경로들은 Git에 포함하지 않은
로컬 자료이며, 저장소를 새로 내려받으면 생기지 않는다. 추적 가능한 검증 요약과 회귀 테스트,
이후 PR의 CI 결과로 저장소 수준의 근거를 확인한다.
기존 [포트폴리오 v1 검증 기록](b2b-portfolio-v1-verification.json)은 당시의 역사 기록으로 유지한다.

## 한계와 전달 상태

브라우저 검증은 Chromium을 사용한다. 인쇄는 브라우저 이벤트와 PDF 생성으로 확인하며
운영체제의 실제 프린터 대화상자나 스크린리더 출력을 수동 검증한 것은 아니다.
새로운 브라우저 저장소, API, DB schema, 실제 인증 또는 운영 권한을 추가하지 않는다.
초안은 페이지 메모리에만 남으므로 사용자가 이탈 경고를 무시하거나 브라우저가 종료되면 사라질 수 있다.

이 검증 기록을 작성한 시점에는 `codex/portfolio-review-ux`의 로컬 미커밋 작업이었으며,
커밋·푸시·PR·병합·배포를 수행하지 않았다. 이후 저장소 통합 상태는 GitHub 기록을 따른다.
원래 제어 checkout은 보존했고, 파일 읽기 지연을 피하기 위해 새 clone의 별도 Git worktree에서 작업했다.

`NOT_PRODUCTION_EVIDENCE`, `productionReady:false`, Issue #165 `HOLD`를 유지한다.
실제 사람의 참여 기록과 정식 실험 집계는 갱신하지 않았다.
