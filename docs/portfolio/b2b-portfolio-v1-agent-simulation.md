# B2B 포트폴리오 v1 — 에이전트 사용성 시뮬레이션

2026-09-26. 사용자가 “너가 실제 사용자라고 하고 진행해”라고 요청하여 Codex가 제품 검토자 역할로 실제 로컬 화면을 조작했다.
수행자는 AI 에이전트이며, 이 기록은 실제 사람의 참여·초심자 이해도·업무 효과 증거가 아니다.
사전 구현 지식이 있는 상태에서 수행했으므로 독립적인 사용자 실험이나 블라인드 평가로도 해석하지 않는다.

## 실제로 수행한 흐름과 판단

| 과업 | 화면에서 확인한 내용 | 에이전트 판단 |
| --- | --- | --- |
| 요구와 후보의 근거 찾기 | R1 단선결선도 인용의 22.9kV와 후보 데이터시트 인용의 24kV. 국내 KR·기본설계·중전압 수배전반. | 수전전압 한 조건의 기술 검토를 진행할 수 있다. 최종 제품 선정은 하지 않는다. |
| 부족한 자료 찾기 | R2의 “승인된 최신 단선결선도”, 전기 설계 담당자 확인 안내. | 이전 값 22.9kV를 이월하지 않고 최신 요구 확인까지 판단을 보류한다. |
| 변경 후 기존 평가 재검토 | R3 개정본 인용의 33kV와 현재 후보 24kV. | 현재 후보를 적합 추천에서 제외한다. 근거 보강과 조건 충족은 별개다. |
| 내 판단 입력 | 세 입력란에 확인 근거·판단 이유·남은 확인 사항을 작성. 입력 중 R2/R3로 이동. | 개정본을 바꿔도 작성한 내용이 유지됨을 확인했다. |
| 판단 기록 내려받기 | 에이전트 구분 선택 후 버튼 클릭. Downloads의 생성 JSON을 읽어 확인. | 작성한 문장, R3, 사례 해시, AI 작성 표시, 사람 참여 false, 정식 실험 기여 false를 확인했다. |

[다운로드 원본 JSON](b2b-portfolio-v1-agent-simulation.json)은 실제 브라우저가 생성한 파일의 복사본이다. 원본의 작성 시각과 입력 내용을 편집하지 않았다.
다운로드 대기용 브라우저 자동화 API는 제한 시간 초과를 반환했지만, 화면에는 요청 완료 안내가 표시되었고 실제 파일도 생성되었다. 파일의 내용까지 별도로 확인했으므로 제품 다운로드 실패로 분류하지 않는다.

## 관찰과 조치

1. **이번 수행자에 맞는 기록 구분 없음 — 보완 완료.** 기존 화면에는 본인 재현과 다른 사람 체험만 있었다. 에이전트 구분, AI 작성 표시, 별도 파일명과 회귀 테스트를 추가했다. 실제 사람의 참여 기록은 만들지 않았다.
2. **`ALLOWED`와 `FIT`의 의미 — 설명 포인트.** R3에서도 근거 사용은 허용되지만 제품은 부적합할 수 있다. 에이전트는 이 구분을 설명할 수 있었으며, 실제 초심자도 이해하는지는 아직 확인하지 않았다. 이를 실제 사용자 실패나 확정 결함으로 기록하지 않는다.
3. **나머지 핵심 동선 — 수행 완료.** 근거 펼치기, 개정본 전환, 다음 확인 자료 찾기, 입력 유지, 파일 내려받기를 실제 UI에서 수행했다. 만족도 점수나 업무시간 절감 수치는 만들지 않았다.

## 남은 범위

- 실제 사람의 면접 리허설과 이해도: 미기록.
- 기존 정식 실험: 확인 당시 0/5명, 팀 기록 0/1건 그대로. 이번 시뮬레이션을 더하지 않는다.
- 실제 제조사 자료, 절연·차단성능·표준 등 추가 필수 사양: 미검증.
- 최종 구매·제품 선정·영업 진행 결정: 미수행.

`NOT_PRODUCTION_EVIDENCE`, `productionReady:false`, Issue #165 `HOLD`를 유지한다.

## 에이전트 구분 추가 당시 변경 검증

에이전트 구분이 없을 때 실패하는 브라우저 테스트를 먼저 확인했고, 구분·내려받기 표시를 추가한 뒤 통과했다.
최종 로컬 검증은 루트 239 + Worker 단위 419 + Worker 계약 28 + 브라우저 16 = **702개 통과**다.
이름·스키마·diff 검사 및 독립 후속 검토도 통과했다. 기존 사람용 내보내기 형식은 유지했다.

이후 #214 수정본과의 통합 검증은 [실행 기록](b2b-portfolio-v1-reproduction.md)의 통합 검증 절에 별도로 기록한다. 이 실제 다운로드 원본은 그대로 보존했다.
