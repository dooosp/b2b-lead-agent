# B2B 포트폴리오 v1 — 근거에서 판단까지

현재 목적은 **채용 면접관에게 한 프로젝트의 요구사항 검토 흐름을 3분 안에 설명하는 것**이다.
2026-09-26 요청에 따라 대표 사례를 한 개로 고정했다. 로컬·오프라인 시연을 제공하며 운영 배포와 구분한다. 첫 진입점은 저장소 루트의 [README](../../README.md)다.

## 바로 실행

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run demo:portfolio:serve
```

콘솔의 `Preview: http://127.0.0.1:...` 주소를 연다. 서버는 루프백에만 연결되고 시연 HTML과 JSON만 제공한다.
종료는 `Ctrl+C`. `npm run demo:portfolio`는 서버 없이 다음 두 파일만 생성한다.

- `tmp/codex/portfolio-v1/index.html`: 외부 리소스 없이 열 수 있는 시연 페이지
- `tmp/codex/portfolio-v1/demo.json`: 입력 지문, 실제 엔진 결과, 개정 비교, 부족한 근거, 출처 추적

HTML을 단독으로 복사해 열어도 세 개정본 전환과 본인 판단 기록 내려받기가 작동한다. 운영 서비스 접속이나 로그인은 필요 없다.
오프라인 동작은 브라우저의 네트워크를 끈 상태에서 자동 검증한다.
생성물과 개인 기록은 Git 추적에서 제외하는 `tmp/codex/portfolio-v1/` 안에 보관한다.

## 고정 사례

**Synthetic DC Alpha / 국내 KR / 기본설계 / 가상 중전압 수배전반 / 수전전압 1개 필수 조건.**
후보의 합성 사양은 24kV다. 평가 시각은 `2026-06-01T00:00:00.000Z`로 고정했다.
24kV와 22.9kV의 비교는 이 합성 엔진의 스칼라 조건 시연이다. 실제 수배전반 선정에는 정격·절연·차단성능·표준 등 추가 요건이 필요하며 이 사례는 이를 평가하지 않는다.

| 개정본 | 현재 요구와 근거 | 엔진 결과 | 검토자의 다음 확인 |
| --- | --- | --- | --- |
| R1 | 22.9kV, 연결된 합성 단선결선도 근거 있음 | `FIT` | 이 전압 조건을 충족함을 확인하고 다른 필수 사양을 검토 |
| R2 | 이전 22.9kV 값만 남음, 현재 요구 상태 `UNKNOWN`, 연결 근거 없음 | `INSUFFICIENT_EVIDENCE` | 전기 설계 담당자에게 승인된 최신 단선결선도와 수전전압 확인 |
| R3 | 새 근거가 요구 33kV를 확인함 | `NOT_FIT` | 현재 24kV 후보를 적합으로 추천하지 않고 다른 후보 검토 |

R2는 추가 근거가 필요한 경우이고, R3는 근거가 확인되어도 필수 조건에 맞지 않는 경우다. R3를 단순한 근거 보강 요청으로 축소하지 않는다.
R1→R2와 R2→R3 모두 입력·근거 변경으로 이전 평가가 무효화된다. 실제 사람의 이전 결정은 입력하지 않았고 자동 대체 결정도 만들지 않았다.

## 질문에 답할 때

- **LLM이 결론을 정하나요?** 이 시연은 결정적 규칙과 검증된 레지스트리 인스턴스를 사용한다. LLM이나 외부 API를 호출하지 않는다.
- **실제 제품에도 적합한가요?** 여기서는 제품군과 합성 사양만 다룬다. 실제 제조사 자료·규격·설치 조건의 검증은 미완료다.
- **업무가 얼마나 빨라졌나요?** 아직 주장할 수 없다. 기존 PR #212의 정식 실험은 0/5명, 팀 기록 0/1건으로 확인했으며 이 시연으로 그 수치를 바꾸지 않았다.
- **왜 모든 초안 PR을 합치지 않았나요?** 대표 검토 흐름에 필요한 변경 비교 모듈만 재사용했다. 데이터셋 확장과 정식 실험 도구는 별도다.
- **FreeCAD와 어떤 차이가 있나요?** FreeCAD는 설계 요구와 형상·도면의 대조를, B2B는 기술정보의 근거·적용 조건을 판단에 연결하는 과정을 보여준다.

## 판단 기록과 사람 평가

페이지의 빈 입력란은 본인 재현 또는 다른 사용자 체험 기록을 파일로 내려받는 용도다. 외부 전송, 서버 저장, 자동 실험 집계를 하지 않는다.
레코드에는 사례 해시, 현재 개정본, 직접 입력한 내용과 기록 시각을 담고 `SELF_REPORTED_NOT_VERIFIED`, `formalPilotContribution:false`를 명시한다.
에이전트가 대리로 사용하는 경우에는 `에이전트 사용성 시뮬레이션`을 선택한다. 이 기록은 `AGENT_SIMULATION`, `AI_AGENT_SIMULATION`, `humanParticipant:false`를 담고 별도의 파일명으로 내려받는다.
실제로 화면을 조작해 작성한 [에이전트 시뮬레이션 기록](b2b-portfolio-v1-agent-simulation.md)과 [브라우저 다운로드 원본](b2b-portfolio-v1-agent-simulation.json)이 있다. 실제 사람의 재현이나 정식 실험 결과로 집계하지 않는다.
테스트에서 생성하는 `SYNTHETIC_BROWSER_TEST` 기록은 검증용 임시 파일로 제거하며 사람의 피드백으로 집계하지 않는다.

면접 시연 준비 후 다른 사용자 한 명에게는 대본을 보여주기 전에 아래 세 질문만 준다.

1. R1을 어느 범위에서 검토해도 되는지 근거를 찾아 설명해 주세요.
2. R2에서 부족한 자료를 하나 찾아 주세요.
3. R3에서 자료가 늘었는데도 후보를 추천할 수 없는 이유를 설명해 주세요.

진행자는 정답을 먼저 알려주지 않고 찾기 어려웠던 곳과 답변을 기록한다. 이 1인 체험은 기존 5인 정식 실험과 별도다. 현재 본인 직접 재현·타인 체험·실무 효과 측정은 미기록이다.
